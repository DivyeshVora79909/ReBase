# MetaSol: current contracts and composable workflows

## Scope and decisions

Backend baseline: `ebe999d`. Frontend baseline: `89799ec`. MetaSol is a separate
repository. Do not stage the user's `accounting-complete.js`,
`populate-full-enterprise.js`, or other unrelated parent files.

Retain Solid, TanStack Router/Query, the native SurrealDB SDK, scoped sessions,
exact decimals, stable write IDs, and optimistic concurrency. Replace obsolete
October 8 accounting assumptions instead of maintaining compatibility paths.
The current build publishes 48 accounting create schemas.

The interface is a workspace for connected calculation facts. A subsidiary's
reporting view, an organization's perspective, and each native account's unit
must remain distinct. Invoices calculate contributions; they are not compliance
documents. Dated exchange pairs/rates are authoritative; observations are not.

## Implementation slices

1. Consume `build/all-in-accounting/client/schemas` and the emitted native field
   metadata at build time. Ship only public schema/type information to the
   browser. Validate with JSON Schema; bind native SDK values from the same
   metadata. Keep field order, helpful labels, and workflow decisions in plain
   frontend modules. Reject unknown/protected fields; retain readonly dimensions
   during editing and preserve exact decimal/datetime values.
2. Replace table scans and offset pagination with reference-based read modules.
   Use `fn::tree::read` for declared account, organization, history and rate
   roots; hydrate returned identities in traversal order. Keep full native
   cursor keys, including tie breakers. Require a leading prefix for composite
   browsing. Filter only bounded visited candidates and retain continuation
   through sparse/empty filtered pages. Detect revision changes and restart
   deliberately. Native inverse references provide bounded lookup/detail lists
   where no ordered tree exists; those lists do not advertise pagination or
   pretend to be indexed arbitrary sorts. Direct ID reads remain primary lookups.
3. Share a schema-aware field and write lifecycle. Use an accessible async
   picker with explicit scope, loading/error/empty states and keyboard support.
   A small flat composer stack keeps the parent draft mounted while creating a
   missing reference. Creation is explicit, with native validation and permission
   checks. Saving a prerequisite does not silently submit its parent.
4. Update accounts, invoices, corrections, claims, taxes, transfers, rates,
   production, analytics and directory to current schema roles. Contextual
   actions pin known parents, expose remaining choices, and offer missing rate
   setup. Remove retired return/refund and analytics fields. Surface related
   records and calculation summaries with named units and perspectives.
5. Simplify navigation and visual hierarchy. Make appearance defaults ordinary
   runtime configuration and allow user overrides. Keep render primitives and
   source callbacks explicit extension points; do not add a resource DSL,
   plugin framework, backend schema editor, or speculative database adapter.
6. Replace the stale disposable demo and maintain native/browser scenario
   suites. Update continuation docs with actual evidence and commit the two
   repositories independently after reviewing the final diffs.

## Acceptance checks defined before implementation

| Boundary | Required scenarios |
| --- | --- |
| Public inputs | All 48 schemas reachable; required/unknown fields; exact decimals; native record keys; optional omission; immutable dimensions; cross-field constraints |
| Index pages | First/next/reverse pages; duplicate timestamps; native cursors; prefix isolation; wrong/missing prefix; sparse filters and empty pages; bounded work; changed revision |
| References | Native inverse traversal; copied IDs; polymorphic targets; scoped results; denied/missing records; no offset/table-scan fallback |
| Workflows | Subsidiary and sparse accounts; invoice issue and payment; missing conversion pair creation with retained draft; dated rate update; correction; production input/output |
| Writes | Database rejection with draft intact; stable ID on ambiguous outcome; optimistic conflict; no retry that creates a duplicate |
| Sessions | Endpoint/tenant/access/epoch isolation; late read/write completion; logout and reconnect; reference scope changes |
| UI | Keyboard selection, clear, escape, focus restoration; empty/error/retry; nested creation; responsive desktop/mobile; theme/density overrides |
| Delivery | Unit checks; current backend build check; disposable SurrealDB integration; maintained browser scenarios; production build; diff checks; excluded user files untouched |

Verification results belong in `verification.md`; this plan is not evidence of
completion. Public tree reads retain native root/member authorization. Backlink
lookups remain bounded result surfaces, not a claim of constant work over an
unbounded relationship. Only introduce another index for a demonstrated query.
